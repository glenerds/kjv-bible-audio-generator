# Engineering Checkpoint — KJV Bible Audio Generator 0.4.7

Date: 2026-11-24  
Status: GUI speaker-import data-loss path fixed; new automated GUI regression; source/wheel verification complete; not customer-ready.

## Problem found

Version 0.4.6 fixed the command-line `--speaker-projections` import by merging machine suggestions with the saved attribution map. A code review found that the desktop `Import Speaker Data (TSV)` button still used the old behavior: it loaded the existing voice registry but did not load `speaker_assignments.json`, then wrote the new imported map over it. A user importing through the GUI could therefore lose manually reviewed verse segments, prior review candidates and user-authored ranges.

## 0.4.7 implementation

- Updated `GeneratorApp._import_speaker_data()` to load any existing saved `AttributionMap` before importing suggestions.
- Both the existing and incoming maps are passed through the same `merge_seed_suggestions()` function used by the CLI.
- Existing exact-text `segment_overrides`, custom/prepared voice profiles, untracked/user ranges, prior `seed_review` candidates and user provenance remain intact.
- The source tracking map replaces only ranges generated by the same suggestion source. A repeated import of an identical source does not duplicate ranges or provenance history.
- Conflicting speakers are queued into `seed_review`; where there is no exact manual override, `segments_for()` retains the neutral `unknown_speaker` result until a human resolves the conflict.
- Review JSON now includes the merged ambiguity queue and merge summary, matching the CLI report.
- The GUI updates in-memory `self.registry` and `self.attribution` to the persisted merged data after a successful import.
- New GUI regression test runs the actual handler with a file-dialog selection, checks manual segment/custom voice/range/review/provenance preservation, confirms overlapping imported suggestions go to Needs Review, and repeats the import to prove idempotency.
